# Resource verification — TLauncher 1.0.3

Correction continuation: Snap, native radio reads and brightness use the existing Dock/utility worker ownership. The picker has only scoped active/visible timers, stops repainting at rest and frees its HWND/D2D/model on close. Radio activation factories are scoped to initialized calls; no permanent Sistema worker is started. Brightness scopes physical handles and does no background polling. These are source/lifetime properties, not measured owner RAM/CPU/GPU results. Hosted radio evidence has zero adapters and brightness reports unsupported (error 50), so real hardware paths and successful physical-handle acquisition/cleanup are not certified by those reads. No owner resource benchmark, local executable run or production modification was performed. Full target-hardware resource comparison remains pending after comprehensive candidate gates.

Target hardware: Windows 11, Ryzen 5 4600G, GTX 1070, 2560×1080 landscape and 1080×1920 portrait. Goals: total app 100–150 MiB RAM, about 3% GPU in normal use and about 1% idle CPU. These are targets. The owner observed low use in standalone FluidWin, without equivalent instrumented data.

These are fixture-process figures, not app-wide totals or a comparison with standalone FluidWin.
