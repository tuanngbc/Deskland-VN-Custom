# Resource verification — TLauncher 1.0.3

Target hardware: Windows 11, Ryzen 5 4600G, GTX 1070, 2560×1080 landscape and 1080×1920 portrait. Goals: total app 100–150 MiB RAM, about 3% GPU in normal use and about 1% idle CPU. These are targets. The owner observed low use in standalone FluidWin, without equivalent instrumented data.

Compare official 1.0.2, official FluidWin 1.3.1, and verified/signed-off 1.0.3 under separately loaded profiles; run them individually. Use the same displays, DPI, hardware/driver, power plan, wallpaper mode and application set. Note the Windows animation and reduced-motion settings. Compare TLauncher with wallpaper off first, then with one equivalent wallpaper workload per display mode to report wallpaper cost separately.

Use identical warm-up, observation and cooldown windows. Measure idle, Dock only, 100 minimize/restore cycles, dragging and Snap, Stage/Dock previews, Settings open/close, Control Center and both Spotlight modes. Log median and p95 frame time and visible startup latency separately from process spawn. Report working set, private working set, private bytes, app and helper process counts, threads, USER/GDI and kernel handles, device/surface/capture session counts and dedicated/shared GPU memory, separately. Normalize CPU across logical processors; report GPU engine utilization without adding unrelated engine percentages. Record spikes and post-close recovery.

Current evidence is limited to synthetic Windows runner workloads. The first Genie run matched source pixels and detected a changed intermediate frame; Scale fixture verified 100 owned-window proxy lifecycles and two external fixture identities. This does not establish full-workload use on the owner hardware. Comparative RAM/GPU/CPU results: NOT_VERIFIED. No automated benchmark ran on the owner's PC. The packaged resource sampler runs only at the owner's request and checks candidate/helper processes; it does not capture the screen or upload data.
