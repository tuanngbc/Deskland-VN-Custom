# Resource verification — TLauncher 1.0.3

Follow-display reuses one Dock HWND/surface and the existing icon/Stage owners. Only explicit Follow mode with multiple connected outputs enables its 80ms cursor-read UI timer; no redraw occurs from an unchanged sample. A two-pixel edge dwell starts the existing temporary spring animation; disable, suspension, single-output topology and exit remove the sample timer. No second Dock, capture worker or global input hook is introduced. Hosted lifetime/topology checks and actual whole-app idle cost remain separate verification gates.

Notification history uses one on-demand Windows threadpool callback only on panel open/refresh or an explicit dismissal. A global admission limit prevents duplicate readers; closing the panel cancels publication and releases its at-most-64-row memory model. No persistent content, listener, poll timer or banner-policy writer is introduced. Original COM reader ownership closes before apartment teardown; native notification strings are bounded and are not logged/exported. This is source ownership analysis, with hosted lifetime verification and total app measurements pending.

Spotlight wave uses the shared ShellGpu with one scoped deferred context, composition swap chain and immutable full-size snapshot. Admission checks the existing adapter budget; failure keeps Spotlight usable without this optional overlay. CPU snapshot memory is released after initial upload and the shader image after ripple completion. All overlay/context resources end after fade/disable/session close; no upstream permanent render thread/device is started. The existing application wait includes the queue-ready handle; a temporary timer only checks failure/visibility. Present never waits while holding the shared context lock. This is source ownership analysis; actual frame pacing and total peak/idle resources remain unmeasured. Hosted readback evidence contains synthetic content only.

Always on Top retains at most 32 small identity/lease records and uses the existing detached Guardian/shared pool. No capture/renderer is created. An 80 ms timer exists only while a guard handshake/enable/release is pending, with bounded UI deadlines; stable pins are checked by the existing Dock refresh and Guardian heartbeat. Normal unpin/disable/lock/exit release the records; no setting is written to source applications or Windows. This is source ownership analysis pending hosted lifetime verification and whole-app measurement.

Border-permission UI uses a scoped activation factory and a transient 80 ms timer only during the directly requested async operation (30-second deadline); no permanent worker or capture session is created by opening the panel. This is source ownership analysis; native lifetime/panel fixtures and whole-app resource measurements are separate gates. Original thumbnail-grid fidelity remains incomplete.
