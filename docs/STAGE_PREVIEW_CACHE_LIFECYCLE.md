# Stage: preview cache and lifecycle

The source key combines HWND, process and thread. A top-level destroy WinEvent invalidates the handle, and every cache sync rechecks identity and capture permission. Visible requests are deduplicated across displays, front layers across cards precede rear layers, and one worker processes one request at a time. A capture stamp (size and caption) and cancellation flag control acceptance. Adding, reordering, switching pages or changing sides reuses the same valid pixels; resize, title, restore or leaving foreground can request a fresh frame.

A newly shown rail displays DWM first and waits 350 ms before waking capture, so rapid toggles do not initialize it for frames that are immediately discarded. One MTA worker shares its D3D11 device across successful requests and releases it after 15 seconds idle. Per-capture graphic resources are scoped and the frame wait is capped at 2 seconds. The cache permits 80 sources and 40 MiB of source pixels. Frames expire after 30 minutes; unused source state also expires. An independent cap of 28 MiB limits the cached idle/hover rasters. A denied or failed capture uses only that layer's fallback. Elevated, cloaked and protected windows can fall back where Windows blocks access; there is no alternate source capture. The worker does not keep a session open to claim live video.

Hiding Stage stops new capture requests, cancels invisible work and releases projected rasters. Switching to DWM or disabling Stage clears source frames. Exit cancels and joins the worker. No product frames are written to disk. The tooltip distinguishes a cached image, DWM, a neutral application icon and a Windows policy denial. A static cached image is never reported as live.
