# Owner UAT: Stage portraits, typography and Win key

**Win key.** The setting is opt-in and takes effect only when Dock mode has successfully hidden the taskbar. The hook queues an inert 0xE8 down/up pair at the first physical Win-down, before deciding whether to open Deskland Start on a tap. It forwards both physical Win edges unchanged, including the release, so a failed injection cannot leave Win held and turn an ordinary Space into Win+Space. Other keys, mouse clicks/wheel or a focus change cancel the Start action; Windows still receives the original chords. If the mask fails (including UIPI) or a hook cannot install, Settings shows the failure; toggle off/on to retry. Windows can silently remove a slow low-level hook; no documented direct health query proves suppression. Start and Compatibility mode do not depend on this listener.

**Input language.** Start and Spotlight carry the foreground app's active input layout into their own UI thread, once, at activation. Try with Gau running: open Start and Spotlight from ENG, type with spaces, close each popup, and check ENG is still selected. Try deliberately selecting VIE via Win+Space; the native shortcut must still work and Deskland must not pin a layout. Also test left/right Win taps on both monitors and Win+E, Win+R and Win+D.

**Stage density.** Six selected cards now fit on one page when at least six separate cards exist and there is enough height for usable previews. Preferred card heights and the automatic gap can yield to the page density; extremely short displays still paginate. Test both monitors with at least seven separate apps and a mix of Auto and custom heights.

Design reference: [Wisp, 38c1d4b](https://github.com/SumirSeth/wisp/tree/38c1d4b619ffdbf4cbcd26fcf69c7bdfc0fbe830), `src/win_key.rs` and `src/hotkey.rs`, MIT. Technical references: [low-level keyboard hook](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc), [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [ActivateKeyboardLayout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-activatekeyboardlayout). No key logging, shell registry edits or Explorer injection.

**Stage.** DWM keeps landscape geometry and aspect-fits tall and near-square windows in a taller inset with room away from the corner icon. The alternative is full contain over a tinted well, not window-image fill or automatic cropping. The source bounds stay intact; rear DWM clips still show only the exposed part of a rear card, with full access through the member picker.

In stacked Stage, right-click the front window and choose **Ảnh phối cảnh · chụp cửa sổ này một lần**. The explicitly requested snapshot is processed on one worker, for that HWND only. There is one pending job and one cached snapshot across Stage, with 360 px maximum retained source side. Protected/unknown-affinity, minimized and cloaked windows are refused. The snapshot uses near/far ratio 1.31 at 28°, a smaller angle on hover, and mirrors its camera on the right without flipping content. No desktop capture or disk output. Close, hide, regroup, change geometry, or choose **Xóa ảnh phối cảnh** to return to regular DWM previews. A WGC error leaves DWM in place; the log reports its API/HRESULT. It is a snapshot, not a live perspective feed. StageDock-Windows source reference includes the pinhole and bilinear design; its desktop-copy fallback was not adopted.

**Type.** Segoe UI Variable Text with Segoe UI fallback; native DirectWrite shaping, grayscale Direct2D rasterization through a per-thread software render target, and GDI fallback. The main Start layout and native EDIT control are retained. Layered glyphs use gray coverage, not RGB subpixel composition. Layout cache is bounded; metric rasters remain keyed by sample and theme. The metrics chip gains width for 10–12 dp text and units, with existing overflow rules.

**Trial sequence.** First compare portrait Chrome/Settings, near-square and landscape Explorer on both Stage sides (compare 1/3/5/8 windows). Try the snapshot on a disposable app window; inspect both edges, app icon, rear hits, and WGC fallback. Inspect Start and Dock in both themes at 100/125/150%, with light/dark backgrounds. In Dock-only mode enable the Win toggle and test LWin/RWin open/close, Escape, then all Windows chords (test Win+L manually only if prepared to log back in). Test both monitors, all taskbar restore paths, toggling off mid-sequence and exit. Native acceptance, real HWND visual evidence and matched CPU/GPU are separate from CI fixtures.

Return to the stable installation using the paired rollback shortcut. Emergency taskbar restore remains Ctrl+Alt+Shift+F12.
