# TLauncher 1.0.3 window motion

## Correction work after both owner rejections

Prepared geometry commands are now implemented for the Dock context menu's maximize/restore and half/expand actions. They use the existing Stage GPU worker, Proxy factory/device and Guardian journal; two accepted source frames precede concealment, native destination observation and the original 300 ms cosine curve at owner speed. There is no new renderer, worker or global Windows-policy setting. A maximized Snap's native fallback retains its pending target until native restore completes. New foreign-window midpoint/native-bounds/recovery fixtures are pending hosted verification, including an independent workflow step so an earlier motion failure cannot hide their result. This supersedes older grouped statements below only for these explicit Dock routes; global titlebar controls, Win+Arrow/Win+Z, the Snap panel and window open/close remain incomplete.

The later `01ca057` run reproduced a different access violation in `dcomp.dll`, reading an unmapped callback address after WGC had closed and its module was absent from the minidump. Consequently the earlier scoped-factory diagnosis below is incomplete. The current mitigation retains one System32 GraphicsCapture DLL code reference until process exit while all actual capture resources still close on demand; three full color-capture rounds stress that teardown. Exact evidence and limits are in `FLUIDWIN_CORRECTION_EXECUTION.md`. This neither establishes the precise OS callback identity nor fixes the owner's border by inference.

Global normal-window Jelly now uses original FluidWin 14×11 spring equations, grip weighting, four integration substeps, DPI-based 80-point displacement clamp and the expanded shader shadow ring. One live WGC session runs on the existing Stage worker, updates the same GPU texture and stops on session release. The existing shared compositor and frame clock draw the mesh. MOVESIZESTART/END observe native dragging; the same Guardian journal owns an alpha-1 visibility lease after two accepted proxy frames, preserving hit testing. Release, cancel, resize, monitor/DPI change, protected source, disable and shutdown restore the source before proxy teardown. Its Settings toggle is opt-in; hosted live-pixel and recovery coverage is pending. Custom-app dragging and dragging a maximized window remain incomplete; open/close/maximize/restore/snap are separate pending routes.

The current controller conditionally leases source visibility through the detached existing Guardian when native Windows animation is enabled. The proxy is presented before concealment; native minimize/restore occurs behind it; reversal keeps the last submitted geometry; release reveals the source before removing the final overlay. Recorded destination bounds are checked against live monitor topology so a native restore's temporary off-screen HWND does not falsely cancel reversal. Source identity, normal placement and DPI remain checked. Existing layered sources retain native fallback. Compatibility-mode recovery is now implemented with the same Guardian in an exclusive motion-only role, waiting for its old role to exit before taskbar takeover; its new complete fixture is pending.

The real WGC color fixture exposed an intermittent access violation on successive capture apartments. Hosted native dump and symbol-map evidence from run `45744158700` maps EXE offset `0x12c537` to `stage_snapshot::CaptureDevice::new + 0x497`, reached by `pump_gpu_fixture` at the second (black) capture after all white poses. The failing address is in activation/device preparation, not a renderer pose. Generated `GraphicsCaptureSession::IsSupported` and `Direct3D11CaptureFramePool::CreateFreeThreaded` use process-wide factory caches; the fixture and restarted capture worker can call `RoUninitialize` between those operations. The adapter now obtains scoped activation factories and invokes their documented vtables while the caller's apartment is alive. It neither pins capture DLLs nor leaves a permanent extra worker alive. This lifetime mismatch is the investigated cause; exact passing-run results are recorded in the execution ledger. The owner's colored-border root cause and quality acceptance remain unresolved independently.

API/source references for that lifetime investigation: [RoUninitialize](https://learn.microsoft.com/en-us/windows/win32/api/roapi/nf-roapi-rouninitialize), [windows-rs generated capture calls at 0.62.0](https://github.com/microsoft/windows-rs/blob/0.62.0/crates/libs/windows/src/Windows/Graphics/Capture/mod.rs), [factory cache implementation](https://github.com/microsoft/windows-rs/blob/0.62.0/crates/libs/core/src/imp/factory_cache.rs). Both previous candidates remain rejected. The motion capture route now uses the existing WGC worker to copy native-resolution BGRA textures directly to a shader-readable texture on the shared device, without runtime CPU readback or thumbnail downsampling. Visible DWM frame bounds determine whether WGC includes invisible resize margins; unexplained dimension differences fall back. Texture allocation uses adapter memory headroom, with an explicit fallback rather than blurry animation. CPU card capture stays separate in the same worker. A hosted fixture requests 2110×980 capture and exports complete rendered targets across Genie, Drop and Scale poses, checking all alpha texels including the perimeter.

The previous capture session did not request borderless WGC, unlike upstream `viva.h`. The shared capture path now requests it and reports the API result. This is a root-cause lead, **not proof** the owner's colored artifact is fixed. [Microsoft's API documentation](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired) notes that permission and other capture clients can still require the border. The native-animation gate and the wider event/Guardian integration remain unfinished. The following paragraphs describe the rejected historical implementation and must not be used as current acceptance evidence.

The Dock calls the existing transition state machine when the user minimizes or restores a window. The app obtains the target from the transformed Dock slot on that output. It uses the existing Stage WGC worker/cache, and creates one click-through, nonactivating DirectComposition proxy. Scale uses the existing surface transform. Genie uses FluidWin's 160-row mesh and pixel shader; Drop uses FluidWin's two-part trajectory, themed chip and clipping at the Dock. The choice lives in the existing motion settings. The global speed and reduced-motion behavior still apply.

The renderer does not change native policy or opacity on foreign windows. If Windows reports native minimize animation enabled or unreadable, it falls back to native behavior. The same applies when the source, capture policy, placement or graphics state cannot be verified. This limitation matters on normal Windows profiles. The [Microsoft DWM attribute documentation](https://learn.microsoft.com/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute) specifies the per-window transition attribute for writes, so copying FluidWin's approach of always restoring FALSE would not guarantee restoration of the previous value. The experiment does not advise turning off system animations.

One-shot Stage frames are bounded and approved before use. Dock motion requests up to 1024 pixels on the long edge and reuses a cached frame only if it has enough detail; ordinary Stage cards remain capped at 360 pixels. The newest transition frame stays at its capture size within the shared Stage cache budget. Older frames are reduced or evicted. A new GPU pass does not create a second WGC session. The proxy still uploads the bounded capture; live GPU-to-GPU capture remains open. Geometry uses physical pixels; owner checks on portrait, ultrawide and mixed DPI are required.

The mesh keeps WGC's premultiplied alpha and builds mipmaps where the device supports them, to filter narrow strips during minification. The running transition can begin immediately when the capture worker returns, with shorter timer intervals and a bounded retry when the compositor cannot accept the final pose. The diagnostic distinguishes fallback reason, capture validity and duration, accepted frame submissions, the longest time between submissions, reversals and final window state. Accepted submissions do not establish on-screen visibility. The hosted fixture checks a WGC source color on screen and probes a changed intermediate frame on a synthetic window.
