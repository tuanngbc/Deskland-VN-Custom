# Unified Spotlight (1.0.2 candidate)

Unified Spotlight runs on TLauncher's existing UI thread. Compact is the original quick search surface; the full-screen native surface adds a paginated application library and an editable Windows search field. The Dock sends its physical monitor position to the same Spotlight owner. Start retains its own surface and Windows-key policy.

- `catalog.rs` builds shared snapshots from Start Menu entries and Windows AppsFolder (packaged apps). Start Menu links are classified by resolved target metadata; document, website, administrative and installer/helper targets are not automatic application tiles. Exact Windows app aliases and identical command targets are deduplicated while manual entries and argument-specific links remain. Discovery and scoped file enumeration run off the UI thread.
- Both Spotlight views reuse application identity, the bounded icon service, the launch resolver and ranked Unicode matching. Files use the existing local directories; the library does not scan all drives.
- `fullscreen.rs` owns native overlay geometry, search generations, keyboard navigation and catalog editing. The rejected DWM extended-frame/GDI path used a black background and normal GDI controls without defined per-pixel alpha; DWM accepting an attribute was not evidence that the composition worked. The owner video showed a gray background and white controls. The repair uses Compact's one-time, downsampled and blurred in-memory sample of the selected monitor, an ordinary opaque RGB surface, a reusable compatible bitmap and premultiplied rounded-control masks. The backdrop is a **static snapshot** while open, not live Acrylic. It is never saved to disk. Transparency-disabled systems use an opaque theme fallback. Hover invalidates only its old/new tile or button, with a short optional fade; icon updates invalidate affected tiles and search results replace the grid atomically.
- `library.rs` stores logical ordering and folder membership. The existing preserving config writer saves `spotlight` and `spotlightLibrary` in the active profile. Custom icons and Dock pins reuse their current TLauncher settings. Hiding or removing a library entry never deletes the original file.

## Owner UAT

After successful CI the developer retrieves and verifies the exact artifact, extracts it in a dedicated UAT directory and prepares one TEST shortcut. Only the owner clicks that shortcut. `owner-uat.ps1` verifies the candidate version, SHA and commit, checks same-session process ownership, uses the existing `--quit` command and waits for the singleton to release. It starts the trial with a separate `tuanpc-desk-trial-…` profile and restores the previously running production when the candidate exits. It never force-kills, overwrites production or modifies production startup. If recovery fails, exit the candidate normally and use the supplied RESTORE-PRODUCTION command. No local build or automated verification is permitted.

1. Press **Alt+Space** for Compact. Type a query, press **F6** to expand without clearing it, and press **F6** again to return. **Esc** closes the overlay, or goes back from a folder.
2. Click the Dock magnifier on each monitor. Only that monitor should be covered. Use **Settings → Shortcuts & Utilities → Unified Spotlight** to choose Dock behavior, theme, sizes and labels.
3. Test an installed Win32 app, an AppsFolder app, a portable EXE and a LNK with arguments. Verify Add, Pin, Hide/Restore, New Folder, drag, remove, and the app-specific menu. No automated test launches the owner's apps.
4. Check the captured frosted material over the wallpaper and an open window, focus return, portrait and landscape displays at mixed scales, and behavior during a display change. Report any unreadable areas or missing apps with personal names hidden in captures.

## Evidence boundaries

The Windows workflow distinguishes Rust unit tests from the isolated native Spotlight fixture. Fixture PNGs exercise the actual composite renderer on a private desktop using a synthetic colored backdrop and labels. The native fixture checks the dirty rect on mouse movement, repeated creation/destruction and handle cleanup; the UAT script contract checks process classification and refusal of ambiguous ownership. They do not prove live OS Acrylic, interactive desktop focus, actual installed app discovery on the owner's machine, the owner's monitor topology, switching the real production instance, or performance relative to 1.0.1. The candidate remains separate from the public release until owner acceptance.
